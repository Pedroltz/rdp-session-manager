# RDP Session Manager 0.6.0

This release introduces a production-oriented server mode for private-network
and VPN deployments, with capacity planning for up to 25 simultaneous
corporate RemoteApp sessions, resource isolation, safer Windows application
launching, and operational health tooling.

## Key Changes & New Features

### 1. Production Server Mode
- Added headless `preflight`, `plan`, `apply`, `capacity`, `status`,
  `benchmark`, and `migrate` commands under `rdpsm server`.
- Added capacity guidance and staged 5/10/25-session load validation for
  deployments targeting up to 25 simultaneous sessions.
- Added atomic xrdp and sesman tuning with configuration backups and automatic
  rollback if validation fails.

### 2. Resource Isolation & Private-Network Security
- Added per-user systemd/cgroup v2 CPU, memory, and task limits.
- Added nftables rules that restrict TCP/3389 to an administrator-provided
  private or VPN CIDR.
- Added server health checks and cached per-session CPU, memory, and process
  metrics to reduce monitoring overhead.

### 3. Safer RemoteApp Sessions
- Introduced version 2 connection profiles with argument arrays instead of
  shell-evaluated application commands.
- Added a shared RemoteApp supervisor with process-group cleanup and structured
  logs, improving session termination and troubleshooting.
- Clarified that RemoteApp is delivered as a single-application xrdp session,
  without claiming native RAIL or seamless-window support.

### 4. Maintained Windows Runtime
- New Windows RemoteApp sessions now use `umu-launcher` with a shared runtime
  cache under `/opt/rdp-session-manager/runtimes`.
- Added checksum-verified umu installation paths for supported distributions.
- Added reversible migration metadata and a legacy WineGE fallback so existing
  prefixes remain usable during rollout or rollback.

Before applying the production profile, review the
[server mode guide](https://github.com/Pedroltz/rdp-session-manager/blob/v0.6.0/docs/SERVER_MODE.md).
